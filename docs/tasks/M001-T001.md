# Task M001-T001

## Objective

Implement and verify the complete deterministic Python ReAct Agent described by Mission M001, including its typed API, bounded trace-producing loop, two safe local tools, CLI, failure handling, documentation, and tests.

## Inputs and Assumptions

- Accepted Requirements and Architecture are the authoritative behavior and component contracts.
- Python 3 with the standard library is available as `python3`; no third-party dependency or installation step is permitted.
- The public API exposes `run(question: str, *, max_steps: int = 5, tools: ToolRegistry | None = None, policy: Policy | None = None) -> AgentResult` or a type-equivalent interface.
- Default deterministic policy behavior must support at least basic binary arithmetic phrased as a short question and exact-key lookup in a documented fixed knowledge table.
- Tests may inject an in-memory policy or tool registry to deterministically reach unknown-tool, invalid-argument, tool-failure, and maximum-step outcomes.
- Expected failures are represented by stable terminal statuses and auditable trace entries rather than uncontrolled process exceptions.

## Forbidden and Out of Scope

- Do not use `eval`, `exec`, dynamic imports for dispatch, `subprocess`, `os.system`, shell execution, network clients, or arbitrary filesystem/configuration discovery.
- Do not add external packages, hosted model/API integration, persistence, concurrency, GUI/web endpoints, or arbitrary user-defined tool loading.
- Do not edit `.chassis`, accepted design artifacts, Git control data, or files outside `allowed_paths`.
- Do not broaden the deterministic question grammar silently; unsupported input must produce a clear, bounded outcome.

## Deliverables

- `react_agent/` modules implementing typed result/trace models, explicit tool errors and registry, safe arithmetic, fixed-table lookup, deterministic policy, bounded orchestration loop, public exports, and `python -m react_agent` CLI.
- `tests/` standard-library unit tests covering arithmetic success, knowledge success, ordered trace content, unknown tool, invalid tool arguments, injected tool failure, exact maximum-step exhaustion, CLI rendering/exit semantics, and a safety scan for forbidden execution APIs.
- `README.md` with the component overview, supported deterministic inputs, Python API example, CLI examples, failure semantics, and exact unit-test and smoke-test commands.
- Passing evidence for CHECK-001 and CHECK-002 within the declared paths and budgets.

## Stop Conditions

- Stop if the task requires a design change or a path outside allowed_paths.
- Stop if a required behavior cannot be implemented with the Python standard library and the explicit in-process tool registry.
- Stop rather than weakening the bounded-step, no-shell, no-network, or no-arbitrary-execution constraints.

## Reviewer Attention

- Verify that every dispatch and parsing path treats user input as data, arithmetic is allow-listed without dynamic evaluation, unknown or failing tools cannot escape the loop boundary, the maximum-step limit is exact, and trace/error rendering does not disclose host details.
